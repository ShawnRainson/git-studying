Урок 1. Что такое Git?

Представь, что ты пишешь книгу.

Без Git у тебя есть:

книга_финал.docx
книга_финал_2.docx
книга_финал_точно.docx
книга_финал_точно_последний.docx

Хаос.

Git делает иначе: он хранит историю изменений.

Например:

Глава 1 добавлена
↓
Исправлена ошибка в главе 1
↓
Добавлена глава 2
↓
Изменён финал

Каждое такое сохранение называется commit.

1. Репозиторий (repository)

Репозиторий — это папка, за которой следит Git.

Например:

my-project/


├── index.html
├── style.css
└── script.js

Когда ты делаешь:

git init

Git создаёт скрытую папку:

my-project/


├── .git/
├── index.html
├── style.css
└── script.js

Вот эта .git — сердце репозитория.

Там лежит вся история.

2. Три состояния файла в Git

Это очень важно.

У Git есть три зоны:

1) Working directory (рабочая папка)

То, что ты видишь.

Например:

index.html

Ты изменил файл.

Git говорит:

"Я вижу изменения, но пока не знаю, хочешь ли ты их сохранить."

2) Staging area (подготовка)

Команда:

git add

говорит:

"Git, подготовь эти изменения к сохранению."

Например:

git add index.html

Теперь файл готов.

3) Repository

Команда:

git commit

создаёт сохранение.

Например:

git commit -m "Добавил главную страницу"

Git отвечает:

"Отлично. Я запомнил этот момент."

Визуально:

Рабочая папка
      |
      | git add
      ↓
Staging area
      |
      | git commit
      ↓
История Git

git commit -m "Описание изменений"

изменения

Что означает git diff?

git diff отвечает на вопрос:

«Что изменилось с момента последнего commit?»

Git сравнивает:

Последний commit
      ↕
Текущее состояние файлов

У тебя было 2 строки, стало 3:

@@ -1,2 +1,3 @@

Можно читать примерно так:

было 2 строки, стало 3 строки.

А строки с:

---
+++

означают, что Git сравнивает старую и новую версии файла.
